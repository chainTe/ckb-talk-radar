## 社区总结

## 今日发生了什么

今天论坛的一条主线是 DAO 提案公平性争论继续，围绕 Rosen Bridge 的资助效果和后续问责展开 [S03, S04, S05, S06]。同时有多项开发、隐私、签名相关提案更新：Sigsheet 发布首个规范草案征求意见 [S01]，Unlinked for CKB 申请 1,000 美元做 Tor 路由 RPC 与浏览器隐私扩展 [S02]，QuotaCell 称已在公共 Pudge 上运行 [S07]。Twine 的 P2P 运营与合规问题 [S16, S17, S18, S19, S20, S21]、CKB Pulse 能否展示使用数据也成为讨论点 [S22, S23, S24, S25]。

## 重点话题

- DAO 提案公平性：Fai 以 Rosen Bridge 为例称桥建好后没有产生有益事情，只有 DAO 资金划给开发者，并追问投赞成票者责任 [S03]；asondev 称太多 CKB DAO 资助项目建成后被悄悄放弃，还有团队把同一项目包装成新提案反复要钱 [S04]；matt_ckb 提到内部网络和老成员支持的现象 [S05]，并回应不应把站外嘲讽的负面情绪带进论坛 [S06]。
- 签名标准化：Sigsheet 首个草案希望让签名者用 ckb-cli、Neuron 或 CCC 应用签署同一笔 CKB 多签交易，并在实现前收集反馈 [S01]；KeyMe 讨论中强调 PSCT 是开放容器而非钱包专用格式，v1 聚焦硬件和 PSCT，v2 再探索与 Neuron 的路径 [S28, S29]。
- Twine：团队提出面向真正需要 P2P 通道的市场做运营和用户增长 [S17]；其说明法币在 Twine 外点对点流转，Twine 不碰法币、不托管 CKB [S18, S20]；社区继续追问起始法币、AML 和本地银行是否允许此类交易，并指出银行转账/接收费用会成为双方现实成本 [S19, S21]。
- CKB Pulse：社区问能否统计已构建项目的使用情况和用户画像 [S22]；维护者回复目前不能，Pulse 展示“谁在建设”而非“谁在使用”，链上使用数据不在其中 [S23]；社区随后希望看到所有 DAO 和 Spark 申请项目的使用情况，并建议比较 Nervos 与其他链的 GitHub 活跃度 [S24, S25]。
- 开发进展：QuotaCell 更新称已离开 localhost、在公共 Pudge 上运行 [S07]；Lock Proof RFC 下有人询问 Rust 后端工具 [S08]，维护者表示参考实现是 TypeScript、Rust 侧目前只有很小的 vm，并愿协助移植 [S09, S11]；Spark Program 下 MoniMkt 提出可复用的 CKB lending 验证工具包并做真实用户测试 [S15]；CKB Escrow Security Test Kit 则解释其通用性来自三层结构，其中只有中间层按项目定制 [S26]。

## 值得继续跟进

- 关注 DAO 资助项目的问责与评审是否会因这轮讨论出现变化；目前争论集中在“建完即弃”和反复融资的风险上 [S03, S04, S05, S06]。
- 关注 Twine 的本地法币选择、AML/银行合规与法币纠纷处理能否给出更具体方案，社区对线下法币环节的疑问仍在 [S18, S19, S20, S21]。
- 关注签名与工具标准化能否落地：Sigsheet 还在收集反馈、尚未写实现 [S01]，Lock Proof 的 Rust 工具化也处于需要移植的阶段 [S09, S10, S11]。
