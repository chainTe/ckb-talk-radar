今日发生了什么

社区今天围绕两个主线展开：一是 Fiber 支付层的新 demo 和隐私提案持续被讨论 [S01, S02, S03, S04, S12, S13, S16, S17]，二是 phroi 发布了一套基于 CKB DAO 存款的链上投票核心设计 [S05, S06, S07, S08, S09, S10]。整体来看，生态项目和基础设施的讨论都比较活跃。[S11, S15, S20, S21]

重点话题

  • Fiber 隐私提案遭社区质询：baclaire 对 ILE_LABS 提出身份核实和项目真实性的直接质疑 [S01]；Ckroamer 建议其先与 Fiber 团队建立联系以保障后续协作 [S02]；Nervosanno 指出该提案声称"已成功实现的架构"与 GitHub 上仅有 8 次提交、无 src/ 目录的实际情况不符 [S03]。项目负责人 Charles Emmanuel 随后公开了 LinkedIn 和 GitHub 以回应身份验证要求 [S04]。
  • phroi 发布 Deposit-Paired Voting 核心设计：这套方案将投票权重与实际 DAO 存款绑定 [S05]，tally 状态写入 live-cell [S05]，连续发布了提案标识机制 [S06]、三类 Cell 模型设计 [S07]、状态机与计票流程 [S08]、取回路径 [S09]，以及可选的委托投票扩展 [S10]。动机来自 Community DAO v1 的经验 [S05]，但 phroi 明确说明这不等同于对任何论坛或治理运营方的共识承诺 [S05]。
  • 两个 Fiber 支付 demo 上线并收到反馈：InkHaven 发布了 Scryve Reads 的"按段落付费阅读"测试网 demo [S12]，但 RetricSu 反馈支付设置（即开通道）的按钮无法使用，并指出 JoyID 在移动端并非最优选择 [S13]。ArthurZhang 则在 EV 充电场景中讨论了 Fiber 的生产级部署问题，强调除支付外还需可信的边缘证书层 [S16]，Sonny 回应称这恰是 demo 与真实部署之间的关键差距 [S17]。
  • Spark 项目进展：Dular 项目获得首笔启动资金 281,800 CKB（20%），首次周报定于 5 月 28 日 [S11]；CKB Developer Onboarding Guide 作者 Mateja3m 就委员会评审结果作出回应，表示尊重决定但仍在进行补充说明 [S15]。
  • DAO 治理机制讨论：ckbbkc 提出关于"点赞"和投票阶段如何防范小团体操控的疑问 [S20]，Yeti 回应称除多账户检测外难以完全阻止，并提到 DAO 1.1 将通过更充分的讨论阶段来改进这一流程 [S21]。

值得继续跟进

  • fiber-payjoin-kit 提案的可信度与后续发展：社区已明确提出代码现状与声明不匹配 [S03]、团队身份待验证 [S01, S04]、Fiber 团队协作前景未明 [S02] 等问题，需观察 ILE_LABS 是否能进一步回应技术细节 [S01, S02, S03, S04]。
  • Deposit-Paired Voting 的社区采纳路径：phroi 的设计已相当完整 [S05, S06, S07, S08, S09, S10]，但尚未看到治理运营方或核心开发者对其集成意愿的表态，其能否从理论设计进入实际应用有待观察 [S05, S06, S07, S08, S09, S10]。
  • Fiber 支付 demo 的 UX 瓶颈：两个 demo 均暴露了从"能跑"到"好用"的间隙——Scryve Reads 的通道设置故障和 JoyID 兼容性问题 [S13]，以及充电场景缺失的边缘信任层 [S16]——这些可能制约 Fiber 在真实场景中的采用速度 [S13, S16]。
