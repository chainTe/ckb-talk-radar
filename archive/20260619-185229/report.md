## 社区总结

## 今日发生了什么

社区今天延续了几条 ongoing 讨论，其中最活跃的是 Luxvoid Protocol 的 DAO 融资讨论和围绕 NDAO 销毁国库资金提案的持续辩论 [S04, S05, S06, S07, S09, S10, S11]。同时，Spark Program 有两项新进展：CKB 钱包行为情报提案进入 Pending 状态，而 Tiko 创作者电商验证冲刺则被拒绝 [S02, S03]。此外，基于 did:ckb 的身份项目 Vellum 发布了声誉扩展方向的新帖 [S12]。

## 重点话题

- **Luxvoid 协议继续争取社区信任**：创始人 Aki 回应了关于客户在哪里以及资金需求的质疑，强调监管趋势（物理到数字的可追溯性）是核心市场驱动力，而非现成客户名单 [S07]；随后又回应 d3fus7.bit 的质疑，承认首次提案需要调整，愿意保持透明并迭代 [S09]。社区成员 ebdalezyz_aljhny 建议将提案拆分为设计、实现、验证、商业运营四个里程碑 [S10]，Aki 表示认同并解释当前两阶段结构已隐含这一逻辑 [S11]。

- **NDAO-0000 销毁提案辩论升温**：janx 继续阐述 DAO 储户利益已通过 Nervos DAO 机制在全次级发行场景下得到保护 [S04]；knmo 补充担忧，认为若让 DAO 用户投票决定涉及自身资金补偿的提案，会造成利益冲突 [S05]；matt_ckb 追问次级发行激活后反通胀补偿是否会增加，试图厘清机制细节 [S06]。

- **Vellum 项目双线推进**：truthixify 发布新帖，将 Vellum 从身份层扩展到声誉层，涵盖 claim、edit、rotate、deactivate、resolve 及 did:plc 迁移等流程的完整方案 [S12]。同时，Hanssen 完成了对 Vellum SDK 代码的审阅并批准合并 [S14]，truthixify 已按建议完成修改 [S15]。

- **Spark Program 两项命运迥异**：CKB 钱包行为情报提案经委员会评审后列为 Pending，认可了 mulinya 的重建和补充工作 [S02]；Tiko 创作者电商验证冲刺虽经重新提交，仍因未满足委员会核心要求而被拒绝 [S03]。

- **Dular 的"电话到公钥注册表"澄清**：Hanssen 解释该注册表是发现/身份层，用于将验证过的手机号映射到 Fiber 身份/接收端点，并非声称每个试点用户都已运行独立的常在线 Fiber 节点 [S13]。

## 值得继续跟进

- **Luxvoid 能否将里程碑建议转化为具体可投票的提案结构**，目前仍处于讨论阶段，尚未形成可执行的 DAO 提案 [S10, S11]。

- **NDAO-0000 辩论中利益冲突与技术机制的张力**：knmo 提出的"DAO 用户自决补偿"冲突与 janx 的技术性保护承诺之间如何调和，可能影响最终投票走向 [S04, S05]。

- **Spark Program 的评审标准一致性**：Tiko 被拒绝而钱包行为情报获 Pending，显示委员会对"验证冲刺"类提案的要求可能更为严格，后续同类申请可观察是否有明确指引出台 [S02, S03]。
